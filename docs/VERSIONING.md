# 版本与兼容策略

## 1. 当前状态

仓库处于初始化阶段，尚未发布稳定版本，也没有承诺任何模块 API。远端存在不代表已经可供商业项目直接接入。

## 2. 仓库版本

首次发布模块后采用语义化版本：

```text
MAJOR：公开合同存在需要调用方迁移的破坏性变化
MINOR：向后兼容地增加能力
PATCH：保持公开合同不变的修复
```

`1.0.0` 只在至少一个真实商业宿主完成接入、升级和回滚演练后考虑。`0.x` 也必须记录变更和迁移，不能把未满 1.0 当作任意破坏调用方的许可。

## 3. 多维合同版本

仓库 tag 不能替代运行时合同。适用时分别维护：

- Lua/C/C++ 公开 API 版本；
- 网络协议与 framing 版本；
- 配置 schema 版本；
- 资产或持久状态格式版本；
- native ABI 与固定 Skynet/Lua 运行时版本。

加载或握手边界必须显式检查版本。未知主版本默认拒绝；允许忽略的新增字段要在合同中说明。

## 4. 弃用与迁移

公开能力弃用时提供替代入口、告警、兼容窗口和删除目标版本。涉及长期状态时同时提供迁移前检查、执行结果、失败回滚和审计记录。

## 5. 依赖固定

Skynet、Lua、编译器、第三方库和 CI Action 都要固定到可审计版本或 commit。升级必须作为显式工程变更，完成 build、运行和相关回归测试，禁止静默跟随浮动依赖。
