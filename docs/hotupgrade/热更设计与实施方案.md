## 组件和接入

HotUpgradeD 是同一 Skynet 节点内的协调 Service：注册元数据、升级事务、批次、版本、超时和审计。它不是独立 OS 进程，不需要 Cluster。宿主已有可信管理入口保存其 handle，通过本地 Service 调用传入 Patch 目录和管理命令。

没有现成管理入口时，由宿主选择一个可信调用点触发；HotUpgrade 不另建管理进程或远程运维通道。首版按单个 Skynet 节点协调；多节点时由已有部署层逐节点触发，是否用 Cluster 由宿主决定。


本地 Runtime 保留 Adapter 函数、Guard、导出 table、StableState 和实例事务；函数不跨 Service 序列化。注册只向控制面传能力及元数据，通过控制消息执行本地 Adapter。

Registry 以 `(service_type, service_id)` 索引，区分逻辑身份、实例身份、地址、generation、code_version、state_version。不同 Service 的代际数字不代表兼容性；组发布身份和版本映射决定兼容关系。

公开门面：Service 使用 `register_service(options)`、`require(module_name)`、`service_ref(options)`、`stable_state(namespace)`。宿主管理入口向协调 Service 发送 `validate/apply/status/history` 等本地命令；`apply` 返回事务身份供查询。

MIGRATE 注册安全点、版本、export/import、healthcheck，以及实际需要的 rebuild_runtime；DRAIN 提供退休条件及生命周期，无须 export/import。控制消息接入显式处理入口，不覆盖宿主 dispatch。

生命周期：`prepare_retire / cancel_retire / begin_drain / can_retire / retire`。有外部副作用的准备必须有恢复能力。Router 内置实现与自定义 Adapter 都必须支持代际、安全暂停、切换、恢复及撤销。

Guard 提供 `run / enter / leave / prepare_upgrade / wait_idle / resume`，异常时计数正确。请求及修改待迁移状态的 Timer、后台任务都必须受 Guard 或等价安全点约束。

统一失败结果含 `ok=false`、`code`、`message`、`step`、`txn_id` 和目标上下文。错误统一 `HU_` 前缀，如 `HU_INVALID_PATCH`、`HU_SAFEPOINT_TIMEOUT`、`HU_DEPENDENCY_CYCLE`、`HU_ABORT_FAILED`、`HU_RESTART_REQUIRED`、`HU_ROLLBACK_NOT_SAFE`。验收映射注明参考规格中无前缀名字的对应关系。

## Module 更新

状态机：`IDLE → STAGING → STAGED → COMMITTING → COMMITTED`；失败进入 `ABORTING → ABORTED`，恢复失败为 `RECOVERY_REQUIRED`。

模块返回普通导出 table。默认更新函数，非函数变化需显式声明，拒绝不兼容类型。删除通过 `remove_exports`。Stage 使用独立缓存和受控 require，不能提前改变线上 package.loaded、导出、配置或状态。顶层不得发消息、启动 Timer、写外部资源等不可逆操作。受限环境减少误用，不宣称是恶意代码沙箱。

多模块按依赖加载，最终绑定稳定导出 table。暂存执行需看到新依赖视图；Commit 后新 closure 不得长期引用脱离线上模块身份的暂存副本。新增模块和内部调用均需测试；未定义循环模块依赖应拒绝。

进入安全点，保存旧导出与版本，再更新、同步 postcheck。单 Lua State 激活与恢复不 yield，检查不做不可逆副作用。部分更新失败恢复导出、版本及新增模块登记。

旧模块 table 引用持续有效，长期缓存 `module.func` 不会自动更新，接入必须通过 table 调用。私有 helper 可 local，需保留状态显式管理。

StableState 只保持当前 Lua State 内 table 身份，Stage 不得改写其线上数据。Service 替换仍需 Snapshot，不自动跨 Service 保留。

## DRAIN 与 MIGRATE

DRAIN 流程：准备旧实例退休、启动候选、检查、发布新代、排空旧任务和引用、退休。

候选 Ready 前不成为 current；发布后兼容旧调用方继续用旧实例，新调用方用新实例。退休需同时满足 can_retire、strong visitor 为零、已接纳请求完成。候选失败先清理其排他资源，再 cancel_retire 恢复旧实例；恢复失败明确报告。准备退休不能切断仍承诺保留的旧调用路径。

MIGRATE 流程：暂停入口、排空、安全点、导出副本、迁移、候选导入、重建、检查、激活、开放流量、退休旧实例。

只修改状态副本，旧状态保留到提交边界。新旧实例不能同时写同一权威状态；旧引用必须受控重绑定或明确拒绝。存在不能排空且不兼容旧调用方时，扩大组或拒绝发布。候选 Timer/后台写入不得提前启动；恢复旧服务及退休时保证任务不重复、过期回调无效。

Snapshot 默认可序列化标量和无环 table，拒绝 function/thread/未知 userdata，限制深度、节点和字节。副本不共用可变引用，迁移前后校验。显式 from/to 链，缺链预检失败；转换确定、尽量幂等，无外部奖励、扣资源等副作用。支持表/二进制 Codec 合同，保留参考要求的分块及外部引用接入能力，不预建无调用者传输系统。

## ServiceRef 与依赖

正常请求使用本地绑定，代际变化时协调。READY 前声明依赖并保留兼容代际资格：仅首次调用才注册引用不足以保护 Late Visitor。

strong 阻止旧目标退休；weak 不阻止，目标失效返回明确错误，不得默默跨代。strict 拒绝未声明依赖，observe 记录违规但不能绕过兼容检查。can_switch 满足且兼容后建立新绑定，再释放旧绑定。

Validate 检查 strong 子图，存在环拒绝；原图含 weak 不代表 strong 子图一定无环。框架不自动改边。

引用释放与在途请求分开追踪；call/send 已接纳但未完成时目标不能提前退休。send 不等于可靠送达，生命周期排空所需确认不能被宣称为通用可靠 RPC。

裸地址调用绕过保证，strict 仅约束受管理入口，不宣称透明拦截任意 skynet.call/send。

## 一致性组与提交边界

组内 Module、Config、Service、Migration 全部 Stage 和检查成功后，关闭入口、排空、激活参与者、确认，再开放流量。各 Lua State 不必同时变化，但生产请求不得观察半激活。候选依赖可绑定组内新候选，仍与生产隔离。

配置区分 stage/activate/abort；旧代码不可看见暂存配置。DRAIN 共存要保留代际配置视图；立即覆盖所有读者的配置 Adapter 不满足保证。不另造 config_loader。

批次不能拆散强耦合组。已成功组保持成功，后续失败为 PARTIAL，不承诺全局原子。

区分提交决定、生产开放和旧实例清理。提交前旧实例存活且 Adapter 满足合同时可 Abort；恢复失败为 HU_ABORT_FAILED，不能伪报成功。开放新流量后只有明确可逆能力才回滚，需重新排空并迁移当前状态，不能切回陈旧状态。

DRAIN 发布后排空超时是清理问题，保留合法新旧实例并记录 `COMMITTED_DRAIN_PENDING`。ABORT 策略仅用于发布前或证明可逆的情况，默认不强杀旧实例。

控制消息带 txn、步骤、实例身份和预期 generation，yield 后重验。超时不代表远端取消，迟到结果不得推进旧事务；未知激活结果时保持相关入口关闭并协调，不同时恢复两个权威写入者。

普通 RPC 定时器不能抢占无 yield 死循环；纯迁移/检查需执行预算，CPU 工作不可长期阻塞 worker。阻塞 Native 不受 Lua 定时器保护，Adapter 必须满足受控执行合同。

必要提交决定先持久化，再开放流量。控制面重启核对参与者及路由，决定继续、撤销或 RECOVERY_REQUIRED。业务 Service/进程崩溃丢失内存不是热更框架能凭空恢复的范围。

## Patch、批次和资源

常规模块热更不要求手写 Manifest。宿主把 Lua 文件放到 Patch Root 下，再将 Patch 目录路径交给 `validate` / `apply`。目录布局约定为 `modules/<Lua 模块路径>.lua`，例如 `modules/chat/player.lua` 对应 `require "chat.player"`。文件路径是模块映射的唯一来源，无需重复填写模块名、目标服务、文件清单或 hash。

协调 Service 遍历目录中的普通 `.lua` 文件，拒绝符号链接和 Patch Root 越界，按路径推导模块名，并计算 hash、冻结源码。目标由已注册 Service 声明使用的模块与 Patch 模块名求交集。无目标、路径冲突、语法错误或代际不兼容时在执行前返回错误。Patch 身份由相对目录与冻结文件内容计算，供事务历史和重复提交检查。

所有目标先完成 Stage，再进入提交；任一目标失败时，提交前恢复已暂存目标。Apply 开始后磁盘文件变化不影响该事务。SHA-256 用于内容完整性和审计，不代替管理入口授权。

Service Replacement、MIGRATE 或需要显式 state/config 版本与选择器时，文件无法可靠推断这些语义。常规模块更新不要求额外元数据；涉及状态转换时，更新文件需包含迁移代码，并按约定提供目标及迁移入口。系统不得猜测迁移方向或自动替换未知 Service。

区分 framework_version、patch_id、code_version、state_version、config_version、service_generation 及组发布身份。

Validate 检查目录边界、文件类型、语法、已注册模块匹配、版本与依赖；有迁移代码时检查迁移链。Dry Run 暂存、副本迁移和安全预检，并释放暂存资源；不能安全模拟的端口释放明确未验证，不动线上资源。

常规模块 Patch 默认更新所有已注册且声明使用对应模块的实例；首版不要求更新者填写选择器。灰度或按 ID 选择属于后续管理能力，不增加简单文件更新的必填描述。

暂停支持 reject 或有界 queue；明确超限、过期结果和恢复顺序，不保证网络全局顺序。History 本地持久化，记录操作者、hash、版本、批次、步骤、错误和恢复状态，内存有界。Metrics 使用轻量 Adapter，不新建监控平台。

已成功 Patch 重复 apply 返回 HU_ALREADY_APPLIED；PARTIAL/恢复中事务不得当新事务重复迁移，恢复必须引用原事务。

## 已确认的文件更新与触发方式

Patch 中的常规模块文件放入 Patch Root 的目录，例如 `PatchRoot/current/modules/chat/player.lua`；该文件对应模块名 `chat.player`。宿主管理入口调用本机的 `flywow_hotupgraded` Service handle，发送 `validate` 或 `apply` 命令及相对 Patch 目录 `current`。协调 Service 返回事务 ID，管理入口再用 `status` 查询结果。

启动协调 Service 属于宿主 composition root 的本地组装，例如由宿主 `skynet.newservice("flywow_hotupgraded", options_module, skynet.self())` 创建，并保存返回的 handle。管理调用使用 FlyWow 热更的本地 Service 消息协议；不需要 Cluster，也不要求单独建立 OS 管理进程。当前代码尚未实现上述免 Manifest 目录扫描和入口约定；本段是接下来实现的设计依据。

管理 Service 在启动阶段保存协调 Service handle，并将它捕获到已有的受信管理命令 handler 中，示意如下：

~~~lua
local hotupgrade_rpc = require "flywow_hotupgrade_rpc"
local hotupgrade_handle

local function start_hotupgrade()
    hotupgrade_handle = skynet.newservice(
        "flywow_hotupgraded", "hotupgrade_options", skynet.self())
end

local function handle_reload_patch(request)
    -- patch_name 必须经宿主允许列表映射为 Patch Root 下的相对目录。
    local started = hotupgrade_rpc.call(hotupgrade_handle, "apply",
        {path = request.patch_name}, 5000)
    if not started.ok then return started end
    return {ok = true, txn_id = started.txn_id}
end
~~~

若宿主没有管理 Service 或命令入口，需由宿主决定一个可信调用点；可以复用启动流程、管理 RPC 或本机控制台。HotUpgrade 只提供本节点内的协调和 Service 消息，不包含远程认证、管理 UI、文件上传或 Cluster 广播。

当前测试命令（从 FlyWow 根目录）：`bash scripts/build_flywow.sh ../skynet hotupgrade`，然后 `bash hotupgrade/scripts/run_hotupgrade_tests.sh ../skynet`。测试审计和日志在 `build/hotupgrade-tests/`，会覆盖测试夹具；不得指向生产审计。
