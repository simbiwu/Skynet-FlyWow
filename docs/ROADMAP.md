# 演进路线

## M0：工程基线

- 独立 Git 仓库。
- P0 架构、模块准入、接入和编码规范。
- 远端、许可证、Skynet/Lua 版本与发布策略待用户确认。

## M1：第一个真实模块

从学习项目选择一个已经运行并经过成功、边界和失败测试的基础能力。迁移时移除课程和具体业务依赖，补齐公开合同、接入示例、独立测试和诊断入口。

候选顺序由学习进度决定，不预先承诺网络、地图或热更谁先进入。

## M2：首个宿主接入

由一个真实项目以显式 composition root 接入模块，记录首次集成成本、缺失合同、配置问题和运维需求，只修正实际暴露的问题。

## M3：第二个消费者

第二个真实项目接入后，验证模块没有携带第一个项目假设。此时再决定公共 Contract、发布载体、兼容窗口和稳定版本策略。

## M4：持续商业化

逐步增加版本发布、兼容矩阵、性能基线、安全审计、故障演练和弃用策略。功能数量不作为里程碑；可预测接入和升级结果才是。
