# 模块准入与完成标准

## 1. 准入条件

课程或商业项目中的代码同时满足以下条件，才进入 Skynet-FlyWow：

1. 解决的是跨项目基础设施问题，不含具体游戏业务规则。
2. 至少有一个真实调用者和可运行实现。
3. 状态 owner、依赖方向、成功和失败语义已经明确。
4. 核心行为已有测试，迁入后能脱离原业务独立验证。
5. 迁移不要求复制业务 DTO、配置表或场景代码。

不满足时继续留在原项目演进，不能用占位接口抢先进入框架。

## 2. 最小模块包

一个可交付模块包含：

- README：解决的问题、非目标、依赖、快速接入和验证。
- Public Contract：入口、request/result、错误、版本和兼容范围。
- Implementation：明确 owner、生命周期、资源上限和清理路径。
- Configuration：字段语义、单位、合法范围、安全默认值和校验。
- Example：只通过公开 API 接入的最小可运行示例；凡存在配置项，必须同时提供可复制的配置 example。
- Tests：成功、边界、失败、关闭/清理，以及适用时的并发/yield 测试。
- Operations：日志、指标、健康状态、诊断和故障处置。
- Upgrade：兼容矩阵、迁移、回滚和弃用周期。

## 3. API 质量

公共 API 应当让宿主明确知道调用是否跨 Service、是否 yield、是否 I/O、谁拥有返回对象，以及所有失败状态。禁止要求调用方解析日志文本判断结果。

配置和协议在边界一次性验证；内部代码可以依赖已验证不变量。未知版本、未知字段策略和超过资源上限都必须有确定结果。所有语言的多行花括号代码按 P0 编码规范使用 Allman 风格；具名 record 字段及成组赋值按语言语法对齐名称、分隔符和值，包含 Native C++、生成物和可复制示例。

代码注释也按读者的理解顺序书写：先说明函数或代码块的用途和结果，再说明参数/状态、单位、前置条件与 ownership，最后解释关键步骤和 WHY。对公式、坐标换算、插值、索引映射等不直观逻辑，给一个简短数值例子帮助读者建立直觉；简单代码无需硬加例子，注释不逐行翻译语法。

## 4. 易接入检查

首次接入者应当能够只阅读模块 README 和一个示例完成：

```text
固定依赖版本
填写最小配置
创建并注入依赖
启动
执行一个真实请求
观察成功与失败
停止并确认资源释放
```

示例不能跳过生产代码要求的校验、错误处理或 shutdown。

## 5. 地图与寻路模块附加要求

地图或寻路模块进入框架时，还必须证明：

- 2.5D Ground 与俯视角 2D 的空间类型、坐标轴、原点、Cell 尺寸和单位有明确合同；
- manifest 包含 map_id、map_version、资产格式版本和内容 hash；
- Path、BattleEvent 和业务位置不把 Grid 索引当作长期公共坐标；
- Unity BMAP、H5/Tiled/JSON 等离线输入有独立导入/校验边界，运行时不读取客户端工程；
- 地图/寻路不依赖 Gateway，Battle 核心不依赖客户端协议；
- 横版平台的重力、跳跃和多层平台若未实现，必须列为非目标并有失败测试。

## 6. 完成定义

只有 build、运行验证、测试、文档、示例和兼容说明全部完成，模块才可标记稳定。编译通过不能替代运行和失败路径测试；基准测试必须记录 Skynet/Lua/native 版本、硬件、负载、参数数量、时长和 GC 条件。

## 7. 每个已交付模块的详细文档门槛

每个已交付模块必须在`docs/<module>/README.md`提供文档入口；文档可以拆分，但链接必须完整，不能只有概述或让接入者猜配置与调用顺序。未实现的候选模块仅记录路线，不创建空接入指南。

每套模块文档必须覆盖：

1. 解决的问题、适用范围、职责边界、禁止依赖和当前未提供能力。
2. 固定依赖、版本兼容、源码/产物目录和构建命令及预期结果。
3. 从首次接入到停止的完整顺序：新建/修改哪个文件、完整示例、执行命令、成功观察点。
4. 所有公开配置：必填/默认值、类型、单位、合法范围、作用域、覆盖顺序、是否可重载和错误行为。
5. 配置 example：配置的 owner、读取者、读取时机、调用入口、复制位置、路径基准；依赖生成物时给出输入、固定工具/版本、生成命令、输出位置、运行时加载点和兼容关系。
6. 所有公开API/消息：参数、返回、失败、来源限制、owner、I/O/yield和生命周期。
7. 跨端模块的两端接入：Client/Server依赖、版本、握手/数据流、编码布局、正常与失败收尾。
8. 最小可运行示例：依赖显式，业务与框架边界清楚，不能以伪代码省略必要步骤。
9. 资源上限、超载、超时、取消、关闭、重试/重复、断线和释放语义。
10. 日志/状态、故障定位、独立验证入口、真实宿主联调及未验证的平台/容量范围。
11. 升级、旧API迁移、配套产物发布与回滚；示例与真实实现同步变更。

Gateway以[完整接入指南](gateway/接入指南.md)和[握手合同](gateway/握手合同.md)作为当前实例。源码、配置或公开合同变化必须同时更新相关文档；缺少详细接入与运维说明不能认定模块交付完成。
