# FlyWow Gateway 接入指南

FlyWow Gateway 是业务无关的 Skynet 接入 Service。它负责 TCP/WebSocket、握手、连接生命周期、Envelope 编解码和 send_data 转发；宿主选择 Gateway 配置并提供 handler Service。Gateway 不选择课程、不 require config.gateway，也不读取 proto 源。

## 目录与协议边界

宿主 Server 使用固定 Skynet 与 FlyWow submodule，协议源位于 shared/protocol/，Server 生成物位于 shared/protocol/generated/server/ 和 server/lualib/gateway/protocol/。

所有课程唯一共用 wire_header.proto 中的 battle.transport.v1.Envelope。每课有自己的 package、CommandId、业务消息、descriptor、Registry 和 Gateway 配置：

- Lesson 1：lesson_01/navigation.proto、lesson_01.pb、protocol_registry_lesson_01.lua、config.gateway_lesson_01.lua。
- Lesson 2：lesson_02/navigation.proto、lesson_02.pb、protocol_registry_lesson_02.lua、config.gateway_lesson_02.lua。
- Lesson 3 帧同步：lesson_03/frame_sync.proto、lesson_03_frame_sync.pb、protocol_registry_lesson_03_frame_sync.lua、config.gateway_frame_sync.lua。
- Lesson 3 状态同步：lesson_03/state_sync.proto、lesson_03_state_sync.pb、protocol_registry_lesson_03_state_sync.lua、config.gateway_state_sync.lua。

Gateway 每次只使用宿主传入的 descriptor_path 和 registry_module；生成的 Registry 在启动校验后直接供 Gateway 查询，不再转换为第二份索引。每个 FileDescriptorSet 包含共享 Envelope 与当前课程类型；它不会因为 include_imports 而包含其它课程协议。

## 生成与验证

协议源修改后，在 WSL 仓库根目录只运行对应课程入口：

    bash server/protocol/build_protocol_lesson_01.sh
    bash server/protocol/build_protocol_lesson_02.sh
    bash server/protocol/build_protocol_lesson_03_frame_sync.sh
    bash server/protocol/build_protocol_lesson_03_state_sync.sh

每个详细注释的独立脚本会校验固定 protoc、生成单份课程 descriptor 和 SHA-256 文件，并调用 FlyWow Registry 工具生成同名课程 Registry。Server run_server.sh 不发现 schema、不生成 Registry。完成构建后可运行：

    bash server/scripts/linux/check_server_descriptor.sh lesson_03_frame_sync

Unity C# 由 Windows 执行 shared/protocol/build_unity_cs.ps1，按课程输出到独立目录。

## 启动与配置注入

composition root 必须先启动并注册 handler Service，再加载本课程完整配置、补上运行时 handler_service，最后启动 FlyWow Gateway：

    skynet.name(".lesson_handler", skynet.self())
    local gateway = skynet.newservice("flywow_gateway")
    local options = {}
    for key, value in pairs(require "config.gateway_lesson_03_frame_sync") do
        options[key] = value
    end
    options.handler_service = ".lesson_handler"
    local result = skynet.call(gateway, "lua", "start", options)
    if not result.ok then
        skynet.error("Gateway 启动失败：", result.code, " ", result.message)
        skynet.abort()
        return
    end
    local gateway_info = result.value

完整配置包含 host、port、transport、descriptor_path、registry_module、protocol_version 和必要的连接、帧长、超时及每连接/实例请求速率上限。handler_service 是运行时本地服务名，不放入静态配置。FlyWow 对可选通用传输参数应用内置默认值，必需协议与 handler 字段由宿主提供；配置、协议文件、Native 依赖或 bind 失败均返回 FlyWowResult 失败值，不报告 Gateway ready；宿主必须先检查 ok，再读取 value。

## 数据转发合同

Gateway 解码客户端请求后向 handler 发送普通 Lua record：

    {
        gateway_epoch = "...",
        connection_id = 123,
        command_id = 1101,
        data = { ... },
    }

宿主处理完成后通过 send_data 返回业务响应，主动 Push 也使用同一入口。connection_id 为正数时定向发送，为 0 时向当前 Gateway 的已就绪连接广播。Gateway 不区分请求响应和主动 Push，不等待 handler 结果，也不保存业务请求关联状态。

Gateway 只负责传输失败语义：未知连接、旧 epoch 或未就绪连接会被丢弃；Protobuf 编码失败会拒绝本次发送；Socket 写失败会关闭对应连接。业务错误、超时、重试、排序和恢复由宿主课程合同处理。
