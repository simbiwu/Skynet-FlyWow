# FlyWow Gateway 接入指南

本文说明业务无关 Gateway 的接入方式。Gateway 负责连接、握手、心跳、协议编解码和数据转发；业务 Service 负责业务处理、业务超时、主动下发和广播策略。

## 1. 目录和依赖

宿主 Server 需要：

    third_party/skynet/
    third_party/skynet-flywow/
    shared/protocol/*.proto
    shared/protocol/generated/server/*.pb
    server/lualib/gateway/protocol/*_registry.lua

FlyWow 是固定版本 submodule。运行时不读取 proto，必须先生成 descriptor 和 registry。

## 2. 协议定义

Envelope 保持最小结构：

    syntax = "proto3";

    message Envelope {
      uint32 protocol_version = 1;
      uint32 command = 2;
      bytes body = 3;
    }

命令通过 CommandId 定义：

    enum CommandId {
      COMMAND_UNSPECIFIED = 0;
      QUERY_CELL = 1001;
    }

命令消息按固定名称匹配：

- QueryCellRequest 与 QueryCellResponse 都存在：请求-响应
- 只有 QueryCellRequest：单向请求
- 只有 QueryCellResponse：服务端主动下发

不定义 service/rpc，不定义 request_id，不使用自定义 option。

## 3. 生成协议产物

从仓库根目录执行：

    bash server/protocol/build_server_descriptor.sh

    python3 server/third_party/skynet-flywow/gateway/tools/generate_gateway_registry.py         --proto shared/protocol/navigation_query.proto         --output server/lualib/gateway/protocol/navigation_registry.lua

Unity 或其他客户端使用同一份 proto 生成消息代码。协议源、descriptor、registry 和客户端生成物必须来自同一提交。

## 4. 启动 Gateway

宿主先为 handler 注册稳定的本地 Skynet 服务名，再创建 Gateway Service 并注入该名称：

    skynet.name(".my_gateway_handler", skynet.self())
    local gateway = skynet.newservice("flywow_gateway")
    skynet.call(gateway, "lua", "start",
    {
        handler_service = ".my_gateway_handler",
    })

名称由宿主选择并避免冲突。Skynet 在每次发送时解析当前注册者；名称未注册期间消息发送失败，Gateway 不排队或重试。
Gateway 不验证 send_data/close 的回复来源身份，因此宿主负责限制哪些本地 Service 可以发送这些命令。

handler 接收 send_data：

    {
        gateway_epoch = "...",
        connection_id = 123,
        command_id = 1001,
        data = {...},
    }

Gateway 解码完成后立即发送 send_data，然后继续读取下一帧。Gateway 不等待 handler 返回值。

## 5. Battle 发送结果和主动消息

请求处理完成后使用同一个 send_data：

    skynet.send(gateway_service, "lua", "send_data",
    {
        gateway_epoch = message.gateway_epoch,
        connection_id = message.connection_id,
        command_id = message.command_id,
        data = response,
    })

主动下发也使用同一个接口。Gateway 不区分响应和主动下发。

指定连接：

    connection_id = 123

广播：

    connection_id = 0

广播发送给当前 Gateway 中所有已经握手成功且仍然有效的连接。某个连接写失败不影响其他连接。

## 6. Battle 关闭连接

业务通过 close 通知 Gateway：

    skynet.send(gateway_service, "lua", "close",
    {
        gateway_epoch = message.gateway_epoch,
        connection_id = message.connection_id,
    })

Gateway 先摘除连接，再关闭底层 transport。close 不取消 Battle 已经接纳的业务操作。

## 7. 跨进程 Proxy

如果 Gateway 与 Battle 不在同一个 Skynet Process，宿主 Proxy 只做透明 Cluster 转发：

    Gateway -> Proxy -> Battle
    Battle -> Proxy -> Gateway

Proxy 只保存远程节点配置和 Gateway Service handle，不保存业务请求，不创建 pending，不生成 route_token，不设置业务超时。

## 8. Gateway 传输保护

Gateway 可以负责：

- 握手超时
- TCP/WebSocket 读超时
- 连接数上限
- 帧大小上限
- 入站限流
- Socket 写失败和连接清理

这些是传输层保护，不是业务请求超时。Battle 自己负责业务超时、重试、顺序和幂等。

## 9. 验证

至少验证：

- TCP 和 WebSocket 握手
- 单向请求
- 请求响应
- 服务端指定连接主动下发
- connection_id=0 广播
- Battle close
- 未知 command
- 错误 descriptor
- 未握手连接不接收业务数据
- 单个广播目标写失败不影响其他连接
