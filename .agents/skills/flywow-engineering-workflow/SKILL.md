# FlyWow 工程工作流

本 Skill 负责工程工作方法，不重复定义编码规范。任何代码修改仍必须遵守 `skynet-flywow-coding-standard`；涉及教学时使用独立的 `source-based-practical-teaching`。

## 任务路由

| 任务 | 读取 |
|---|---|
| 新需求、架构讨论、模块设计、合同梳理 | `references/需求分析与方案设计.md` |
| 按已确认方案实施多文件或跨模块修改 | `references/分阶段实施.md` |
| 代码审计、提交 Review、最小化审计、复杂度整改 | `references/代码审计与复杂度审计.md` 和 `references/反模式与架构重置.md` |
| 复杂、间歇性或根因不明的 Bug | `references/调试与根因分析.md` |
| 审计发现涉及多余抽象、重复防御、状态冗余或架构级简化 | 追加读取 `references/反模式与架构重置.md` |

简单局部修改不需要启动完整工作流。用户只要求审计时只审计，不擅自修改；用户要求实施时才修改。

## 工作原则

1. 先理解真实需求、现有合同和实际生产调用链，不根据文件名或局部代码猜测职责。
2. 方案作者、实施者和审计者都必须遵守 KISS。方案本身不能把复杂度判断留给用户或 Codex 补做。
3. 技术事实必须核实到当前项目实际使用的版本、公开 API、Binding 和调用路径；未经验证的推测不能变成设计约束。
4. 新增类、接口、状态、包装层、检查、断言、Fallback、恢复机制和配置，都必须对应当前真实问题。
5. 不把现有调用者、测试、样例、文档或“代码已经这样实现”当成设计合理性的充分证据。
6. 保护机制要追溯其保护对象和真实风险。若保护对象或交互关系来自可能不必要的内部设计，先审查该设计，再决定保护机制是否仍需要。
7. 不为追求代码少而删除真实的外部信任边界、授权验证、并发保护、资源所有权、生命周期约束、失败合同或公开 API。
8. 不以函数行数、类数量、文件大小、抽象层数量等机械阈值代替设计判断。
9. 证据不足时标记“尚未证实”，不能证明某个设计多余不等于已经证明它必要。
10. 不强制使用 Subagent、Worktree、TDD、ADR、任务跟踪器或额外框架。只有任务和现有工程确实需要时才使用。
11. 用户目标约束审计和实施范围。不得把可选优化、一般风险治理或助手推测的需求转成必改项；“完整实施/收口”只覆盖当前目标内已成立的整改项，不扩大授权范围。

## 设计和实施边界

- 用户已确认方案并明确授权实施时，按方案执行，不重复要求确认。
- 方案与真实源码或既有合同冲突时，暂停冲突部分，指出证据并给出最小替代建议；不得自行改合同。
- 发现会改变公开 API、参数/返回合同、错误码、协议字段、状态 owner、生命周期、调用顺序、失败恢复或外部副作用的实质变化时，向用户说明影响并等待决定。
- 修改公共合同时，追踪并更新所有直接受影响的生产调用方、测试、样例和文档；只改内部实现且合同不变时，不顺手扩展到无关模块。
- 不以测试通过、内部文档引用或现有调用者存在作为合同变更授权。
- 不顺带重构与任务无关的代码。
- 交付时区分实际验证、源码推导、测量结果和未验证内容。

## 用户目标与整改范围门禁

审计和实施前先写清用户要求达到的效果、适用合同及本次范围。每项发现都要证明它如何影响该目标或违反哪条既有合同；不得因“可能发生”“更健壮”“商业级”或“符合常见做法”自动转成整改要求。

结论分为“本次必改”和“可选建议/范围外观察”。前者必须属于当前目标，并有明确规则/合同违反、可复现或可达的错误行为，或经调用链证明的设计复杂度问题作为依据。后者不进入整改清单和验收条件；用户要求实施审计结果时，也不因此获得实施授权。涉及新增策略或可观察行为变化时，先说明收益、维护成本、行为变化及其与目标的必要关系；目标未要求且必要性未证实时，不实施。

风险、性能、容量、容错、安全强化等内容可作为单独审查维度，但只有用户要求审查该维度，或它直接造成当前目标/合同不成立时，才能形成必改项。发现风险不等同于判定复杂度、缺陷或规则违反。

## 审计结论

每个审计发现归入以下一种：

- **保留**：有明确且无法用更简单方式满足的真实需求或合同。
- **简化**：能力必要，但实现可以更直接。
- **合并**：多个结构可由一个有清晰 owner 的结构承担。
- **删除**：没有真实消费者、决策用途或不可替代的合同价值。
- **替换**：用更简单的完整实现满足相同需求。
- **尚未证实**：现有证据不足，不能直接判定保留或删除。

主文件只负责路由和共同原则。具体方法以当前任务对应的 reference 为准，不要求每次加载全部 references。
