# 注释与可读性补充规范

本文件补充现有 Coding Standard 的注释交付门禁和命名规则，不降低原规则要求。

## 注释目的

注释应帮助维护者理解业务含义、数据来源、owner、生命周期、关键约束和非显然行为。不要逐行翻译代码，也不要用阶段标签替代具体说明。

## 调用链可读性

同一业务对象沿连续调用、转发和保存过程应保持可追溯的领域名称。只有对象语义实际改变时才换名，并在转换处说明输入与输出关系。

避免让读者在多个文件和 Helper 之间跳转，才能弄清简单操作的真实效果。主流程应能呈现主要输入、状态变化、关键处理和输出。

## 状态说明

跨函数共享状态在声明处或集中定义处说明业务含义、owner、写入/读取位置和状态变化原因。不要为每次读取重复解释，也不要用多个同义名称描述同一个事实。

## 注释与复杂度

注释不能为不必要的封装制造合理性。若某个对象或状态本身可删除，其专属注释、LuaDoc、测试和内部文档也应一并评估；公开合同注释不得擅自删除。
