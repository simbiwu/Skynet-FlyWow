# Lua Binding 使用说明

本库帮助 Native 函数读取 Lua 参数、操作 table、构造返回值和管理 userdata。普通函数直接书写，在注册处接入 C++ 异常边界；无需编写入口 lambda。

固定基线为 C++17、Skynet v1.8.0 自带修改版 Lua 5.4.7。实现只依赖 Lua 与 C++ 标准库；静态 target `flywow_lua_binding` 链接进各 Native 模块，不单独生成可 require 的 Binding 模块。

## 完整接入示例

Lua 传入 `{map_id=0}`，Native 严格读取整数并返回新表。整数 0 是合法值；数字字符串应被拒绝。

```cpp
#include "lua_binding.h"
#include "lua_table.h"
#include <cstdint>

using flywow_lua_binding::LuaBinding;
using flywow_lua_binding::LuaTable;

// 参数 1 为请求表；成功返回新表，类型错误返回 nil,{code,message}。
int read_map_id(lua_State *state)
{
    LuaBinding binding(state);
    LuaTable request;
    std::uint32_t map_id = 0;
    if (!binding.readTable(1, request) || !request.readValue("map_id", map_id))
    {
        return binding.pushError();
    }

    LuaTable result;
    if (!binding.newTable(result) || !result.writeValue("map_id", map_id))
    {
        return binding.pushError();
    }
    return binding.returnValues(result);
}

// 模块入口只使用静态函数表和 Lua 值，注册失败沿 Lua 加载错误传播。
extern "C" int luaopen_example(lua_State *state)
{
    static const luaL_Reg functions[] =
    {
        {"read_map_id", &LuaBinding::nativeCallback<read_map_id>},
        {nullptr, nullptr},
    };
    luaL_newlib(state, functions);
    return 1;
}
```

Lua 侧调用：

```lua
local native = require "example"
local result, err = native.read_map_id({ map_id = 0 })
if result == nil then
    print(err.code, err.message)
else
    print(result.map_id)
end
```

`nativeCallback<read_map_id>` 是注册函数指针，无隐藏 upvalue，也不修改正常返回值。C++ 意外异常经过此处时，实际函数中的资源已展开，再返回 `nil,{code="INTERNAL_ERROR",message=...}`；OOM 不作为业务恢复场景，行为交由运行时及宿主处理。领域错误继续由业务函数明确返回。

## 构建与 Sample

宿主必须先构建自己的 Skynet Lua，包含头文件和 `3rd/lua/liblua.a`。从 FlyWow 根目录执行：

```bash
bash scripts/build_flywow.sh /path/to/skynet lua_binding
bash lua-binding/sample/run_lua_binding_sample.sh /path/to/skynet
```

这两个命令在实际执行时都会使用指定 Skynet 自带 Lua ABI。ABI 测试复用指定宿主的 `lualib-src/lua-sharetable.c`，不修改其源码。构建入口先编译 `flywow_lua_binding` 并运行 `flywow_lua_binding_test`；Sample 脚本随后再编译、运行示例。Sample 成功标记为 `FLYWOW_LUA_BINDING_SAMPLE_OK`。文档中的标记是成功条件说明，不代表未执行命令时已经验证。

中间产物位于 `build/cmake/lua-binding/`，Sample 产物位于 `build/lua-binding-sample/`。宿主链接 `flywow_lua_binding`，不链接另一套系统 Lua。

## ABI 回归覆盖

真实 ABI 测试位于 `lua-binding/tests/lua_binding_test.cpp`，由 `bash scripts/build_flywow.sh /path/to/skynet lua_binding` 构建并经 CTest 执行。测试必须链接所传 Skynet v1.8.0 的 `3rd/lua/liblua.a`，不能以系统 Lua 替代。

测试使用独立 Lua State 检查：严格数值和字符串转换、失败时输出与栈恢复、table raw 读写和迭代、registry 引用释放、业务 upvalue 编号及大闭包、C++ 异常转换、共享表写入失败的错误诊断和栈恢复、动态 userdata 注册、静态 `require` 模块注册成功及 `__gc` 覆盖拒绝、析构幂等、State 隔离与关闭析构。测试覆盖的是 Binding 的 Lua ABI 和生命周期合同；它不代替 Gateway/Navigation 等各 Native 模块的宿主集成验证。

Sample 使用的是更小的真实调用示例；它会先触发上述 ABI 回归，再单独编译和运行示例程序。

## 三个类型与 ownership

| 类型 | 职责 | 生命周期 |
| --- | --- | --- |
| `LuaBinding` | 本次 Native 函数的参数、错误和结果；保活借用 userdata | 当前同步回调，不拥有 State |
| `LuaTable` | 用独立 registry 引用操作同一张表 | 早于所属 Binding 销毁，可移动、不可复制 |

父子 LuaTable 各持独立引用，可以独立销毁。将表写入别的表或返回给 Lua 后，句柄析构只释放自己的引用，不销毁 Lua 仍持有的表。句柄不能跨回调、跨 State 或 yield；同一 State 的不同 Binding 句柄也不能混用。

## 参数与字段

读取接口成功返回 true；类型或范围错误返回 false，并记录 Binding 诊断，保持输出值不变。C++ 意外异常由注册处 nativeCallback 处理。OOM 不承诺返回 false、恢复 C++ 栈资源或维持业务可用性，交由现有运行时及宿主处理：

```cpp
binding.readValue(1, value);
binding.readOptionalValue(2, default_value);
binding.readTable(1, request);
request.readValue("map_id", map_id);
request.readTable("position", position);
request.writeValue("map_id", map_id);
request.writeValue(1, value);
request.writeValue("removed", nullptr);
```

`readOptionalValue` 只在参数省略或为 nil 时保留默认值。false、0、空字符串都是真实输入，按目标类型校验。严格 bool 读取仅接受 boolean；`readTruth` 显式采用 Lua 真值规则，只有 nil 和 false 为假。

整数转换检查目标 C++ 类型范围；整数接口不接受浮点 1.0 或数字字符串。浮点转换拒绝非有限值。`std::string` 保留内嵌零字节；C 字符串按首个零字节结束。

table 使用 raw 读写，不触发 `__index`、`__newindex`。普通表允许写入 `__gc` 字段。托管 userdata 元表的析构方法由类型注册入口设置；LuaTable 按实际元表与析构闭包身份拒绝后续删除或覆盖，换一个句柄也不会绕过保护。保护复用析构闭包的私有元数据，不增加注册表或句柄状态，也不改变业务方法的 upvalue 编号。直接使用原生 API 改写托管元表不在此保护合同内。

`isNil(key)` 对 nil 返回 true；非 nil 或无效句柄返回 false。使用者先检查 table 的创建/读取结果，不能用 isNil 代替句柄有效性检查。

## 创建和返回

```cpp
LuaTable output;
if (!binding.newTable(output))
{
    return binding.pushError();
}
if (!output.writeValue("accepted", false))
{
    return binding.pushError();
}
return binding.returnValues(output);
```

`newTable(output)` 创建完成后替换 output，并由句柄接管 registry 引用。`returnValues` 支持零个或多个结果：

```cpp
return binding.returnValues();
return binding.returnValues(false);
return binding.returnValues(table, value);
return binding.pushError();
return binding.pushError("MY_ERROR", "operation failed");
```

结果按实参顺序交给 Lua。成功值允许 false 时，Lua 调用方使用 `result == nil` 判断失败。准备返回结果后立即 return，不另行弹栈。

## 注册方法与业务 upvalue

使用静态 `luaL_Reg` 注册函数，回调接入异常边界：

```cpp
static const luaL_Reg functions[] =
{
    {"read_map_id", &LuaBinding::nativeCallback<read_map_id>},
    {nullptr, nullptr},
};
luaL_newlib(state, functions);
return 1;
```

需要业务 upvalue 时由模块入口使用 Lua C API 创建闭包，回调通过 `readUpvalue` 读取真实业务槽位；绑定不提供写入 upvalue 的 API。外部指针只借用，owner 必须覆盖闭包生命周期。

模块初始化使用静态 `luaL_Reg` 表；不需要为注册模块创建 LuaTable 或 Binding 对象。初始化中若有 C++ 单例、容器等可能抛出的操作，应在局部 try/catch 中处理，并在资源与异常对象销毁后调用 Lua 错误出口。

## userdata

模块入口的静态注册接口：

```cpp
static const luaL_Reg methods[] =
{
    {"close", &LuaBinding::nativeCallback<close>},
    {nullptr, nullptr},
};
LuaBinding::registerUserdata<MyObject>(state, "example.MyObject", methods);
```

它安装受控的 `__gc`，并把 methods 表设置为 `__index`。类型名必须非空且在本 State 中唯一；methods 不能覆盖 `__gc`。失败沿 Lua 模块加载错误传播。

普通回调中创建和读取对象：

```cpp
MyObject *object = nullptr;
if (!binding.newUserdata("example.MyObject", object, constructor_argument))
{
    return binding.pushError();
}
return binding.returnValues(object);
```

`newUserdata` 先分配 Lua-owned 存储和禁用的 GC 标记，再在 C++ 作用域构造 T；构造成功才启用析构标记。T 必须 noexcept 析构并满足宿主 Lua 的对齐要求。参数错误、未注册类型、构造失败返回 false。已构造对象在后续失败时仍归 GC，析构时间可能晚于本函数返回。

`readUserdata` 验证精确元表与存活标记。T* 只在本 Binding 同步回调内借用，不得 delete、跨线程或长期保存。Binding 内部引用用于将指针还原为原 userdata 并防止借用期间被 GC。业务 close 释放内部资源；之后 GC 仍可安全调用析构。

userdata 类型只在模块入口通过静态注册建立。

## 遍历与数组

LuaTable 保留字段读写、Lua 真值读取和 `denseArrayLength`；不提供通用遍历或 Lua 元表读写接口。

`denseArrayLength` 验证正整数 key 恰为 1..N，忽略其他 key，空表长度为 0。业务自己决定是否允许空数组。

## 内部维护入口

核心路径只有以下几种：

| 操作 | 内部执行 |
| --- | --- |
| 严格参数读取 | 原位检查类型与范围，不改变参数栈 |
| table 字段读取 | 直接 raw 读取并严格转换，随后恢复临时栈 |
| table 字段写入 | 一次 lua_pcall 捕获共享表只读等正常 Lua 错误，随后恢复临时栈 |
| C++ 业务处理 | 在普通函数作用域执行，由注册处兜底异常 |
| 模块加载 | 静态表直接注册，使用 Lua 加载错误合同 |

建表、建立 registry 引用、读取 userdata 和压入返回值直接调用 Lua C API，不为 OOM 增加保护回调、参数记录或恢复流程。类型、范围、元表身份和 alive 检查继续报告原有诊断，userdata 强引用与 GC 析构责任保持不变。

只有字段写入保留 `lua_pcall`：Skynet 的共享表禁止修改，raw 写入同样会抛出非 OOM Lua 错误。回调只执行 Lua API 和不持有待析构资源的转换逻辑，`completeCall` 将错误记录为 Binding 诊断。`returnValues` 按返回项数量通过 Lua API 预留栈空间；`StackRestore` 负责恢复临时栈。`newUserdata` 保留普通构造异常的引用清理，`nativeCallback` 保留 C++ 异常入口，不再单独诊断 bad_alloc。

LuaTable 内部自动恢复临时栈；registry 引用保持对象身份。直接混用原生 Lua C API 时，调用者仍需处理自己的栈与 longjmp 边界。

## 迁移清单

| 旧写法 | 当前写法 |
| --- | --- |
| 入口 invoke 加 lambda | 直接函数体，注册 nativeCallback<函数> |
| 模块 invokeModule 加 lambda | 静态 luaL_Reg 直接注册 |
| `auto table = binding.newTable()` | `LuaTable table; binding.newTable(table)` 并检查 bool |

## NativeData：C++ 数据树与 Lua 字段访问

NativeData 使用独立的直接 Native 入口：`require "flywow_native_data"`。
产物是 `build/native/flywow_native_data.so`，入口是 `luaopen_flywow_native_data`；
没有 Lua Wrapper。它与通用静态库 `flywow_lua_binding` 是两个不同的产物。
调用方将该目录加入 `package.cpath`（Skynet 使用对应的 `lua_cpath`）即可加载。
通过现有构建入口生成，无新增构建模式，可从任意目录调用：

```bash
bash /absolute/path/to/skynet-flywow/scripts/build_flywow.sh /absolute/path/to/skynet lua_binding
```

上述两个路径分别是 FlyWow 和已构建的宿主 Skynet 根目录；
宿主 Lua 必须为 Skynet v1.8.0 自带修改版 Lua 5.4.7，不能替换成系统 Lua。
`navigation`、`all` 模式同样构建此产物。新增 ABI 测试与旧 Binding 测试一起执行；
新增场景成功标记是 `FLYWOW_NATIVE_DATA_OK`。

```lua
local NativeData = require "flywow_native_data"
local player = NativeData.new()
player.hp = 1000
player.online = false
local source = { attack = 20, bag = { "sword", "potion" } }
player.attr = source
source.attack = 99
assert(player.attr.attack == 20)
local attr = player.attr
attr.attack = 30
assert(player.attr.attack == 30)
player.copy = attr
assert(player.copy ~= attr)
player.attr = nil
assert(not pcall(function() return attr.attack end))
```

字段支持 string/integer 键和 boolean、int64、double、二进制安全 string、嵌套
Lua Table、NativeData 代理值。nil 删除字段，缺失返回 nil，false 保持为真实值。
浮点键（直接访问时包括 1.0）及其他键类型非法；Lua Table 已自行归一化的整数键按整数导入。
Lua Table 通过原始字段递归导入，不复制元表或执行 __pairs。
只拒绝当前递归链上的环，同一来源子表在不同位置独立复制。失败保留旧字段。
Native 代理赋值先 clone 再替换，包含 `player.attr = player.attr`，不会共享子节点。

`#player` 是从整数键 1 开始连续存在的长度；`ipairs` 到第一个缺失项结束；
`pairs` 按 Native map 的整数键、字符串键顺序遍历。遍历中禁止增删当前容器字段。
相同节点的不同代理用 == 比较为真；深拷贝后的不同节点为假。
对象是 Full Userdata，不支持 rawget/rawset 或要求真实 table 的 table.insert/remove/sort。

### 其他 Native 模块直接接入

业务 Native 模块包含两个头文件，并直接链接已有 `flywow_lua_binding` 静态库：

```cpp
#include "lua_binding.h"
#include "lua_native_data.h"

using flywow_lua_binding::LuaBinding;
using flywow_lua_binding::LuaNativeData;

// 当前同步回调创建一个根，并通过既有结果转换入口返回同一个对象。
int create_player(lua_State *state)
{
    LuaBinding binding(state); // 当前回调的参数、诊断及返回出口。
    auto player = std::make_shared<LuaNativeData>(); // 根的首个 owner；Lua 返回时共享它。
    player->set("hp", std::int64_t{1000});
    return binding.returnValues(player);
}

// 只在当前回调借用 Lua 传入节点；失败沿现有 Binding 错误合同返回。
int update_player(lua_State *state)
{
    LuaBinding binding(state); // 保活参数 userdata 到同步回调结束。
    LuaNativeData *player = nullptr; // 本次借用，不跨 yield 或长期保存。
    if (!binding.readNativeData(1, player))
    {
        return binding.pushError();
    }

    player->set("hp", std::int64_t{1500});
    return 0;
}
```

注册上述函数时使用 `LuaBinding::nativeCallback<create_player>` 和
`LuaBinding::nativeCallback<update_player>`；返回根不要求事先 require 专用模块。
每个 Lua State 幂等注册同一个具名元表，其他 Native .so 可以互传并读取根或子代理。
测试将同一测试源分别编译为两个独立 .so，分别链接静态 Binding，通过真实 require 验证双向互操作。

根由 C++ 与 Lua 根代理共享所有权；C++ 若需长期持有，保存根 shared_ptr。
每个字段子树归父 unique_ptr 独占，Lua 子代理只有 ProxyState，不保活根或子树。
删除/替换节点及最后一个根 owner 释放后，旧代理读、写、长度与迭代统一抛出
`LuaNativeData node has expired`。修改节点内部字段不会让该节点代理失效。
根代理变量赋 nil 本身不立即释放树，实际释放由最后一个根强 owner 结束决定。
C++ get 返回的字段地址只在对应字段未修改期间有效；借用子节点在被删除后立即失效。

### V5 合同与当前 Binding 的已确认适配

V5 引用的旧 `detail::protectedCall` 已从当前 Binding 移除。此次实施按用户确认，
沿用当前直接 Lua C API 路径，不为 OOM 恢复旧保护调用，也不改变其他类型的结果转换合同。
OOM 交由运行时和宿主处理，不承诺其发生后的 C++ 展开或继续运行。
普通非法键/值、递归环和失效节点通过 C++ 展开临时值后由元方法出口抛出 Lua error；
普通 Native 函数使用 readNativeData/pushError 的 nil/error 合同。
Lua new 复用 returnValues；因 new 是 C++ 关键字，回调使用 new_native_data，
保留 V5 固定 Lua 名称。NativeData 直接 .so 命名也是该合同指定的例外。
没有新增 Manager、公共 push/read 自由函数、Lua registry 业务数据引用或独立错误体系。

### 最小化审计整改

此次整改保持公开 API、节点所有权和错误合同，具体变更如下：

- readValue 每层导入 table 前使用 lua_checkstack 预留 4 个槽位：
  key/value 两槽，嵌套 userdata 的精确元表检查再用两槽。
  容量不足通过现有 C++ 展开和元方法错误出口报告，不新增栈管理对象或 OOM 恢复。
  回归用例包含 256 层合法 table，以及深层非法字段失败后旧目标仍完整保留。
- pushValue 删除临时 std::string 副本。固定宿主的 lapi.c:lua_pushlstring
  先执行 luaS_newlstr 并压栈，随后才检查正常 GC；OOM 紧急 GC 仍按已确认宿主规则处理。
- 元表幂等注册从 pushProxy 移至根 ValueCodec::push。
  子代理来自已经过精确元表验证的节点，直接挂接已有元表，无额外“已注册”状态。
- GC 压力测试检查 pcall 的成功载荷和错误文本，避免吞掉类型、字段或迭代错误。
- CMake 将原有与新增 ABI 测试收在一个测试条件块中，编译诊断就近设置，不新增构建封装。
