# Lua Binding 使用说明

本库帮助 Native 函数读取 Lua 参数、操作 table、构造返回值和管理 userdata。普通函数直接书写，在注册处接入 C++ 异常边界；无需编写入口 lambda。

固定基线为 C++17、Skynet v1.8.0 自带修改版 Lua 5.4.7。实现只依赖 Lua 与 C++ 标准库；静态 target `flywow_lua_binding` 链接进各 Native 模块，不单独生成可 require 的 Binding 模块。

## 完整接入示例

Lua 传入 `{map_id=0}`，Native 严格读取整数并返回新表。整数 0 是合法值；数字字符串应被拒绝。

```cpp
#include "lua_binding.h"
#include "lua_table.h"
#include <cstdint>

using flywow_lua_binding::LuaBinding;
using flywow_lua_binding::LuaTable;

// 参数 1 为请求表；成功返回新表，类型错误返回 nil,{code,message}。
int read_map_id(lua_State *state)
{
    LuaBinding binding(state);
    LuaTable request;
    std::uint32_t map_id = 0;
    if (!binding.readTable(1, request) || !request.readValue("map_id", map_id))
    {
        return binding.pushError();
    }

    LuaTable result;
    if (!binding.newTable(result) || !result.writeValue("map_id", map_id))
    {
        return binding.pushError();
    }
    return binding.returnValues(result);
}

// 模块入口只使用静态函数表和 Lua 值，注册失败沿 Lua 加载错误传播。
extern "C" int luaopen_example(lua_State *state)
{
    static const luaL_Reg functions[] =
    {
        {"read_map_id", &LuaBinding::nativeCallback<read_map_id>},
        {nullptr, nullptr},
    };
    luaL_newlib(state, functions);
    return 1;
}
```

Lua 侧调用：

```lua
local native = require "example"
local result, err = native.read_map_id({ map_id = 0 })
if result == nil then
    print(err.code, err.message)
else
    print(result.map_id)
end
```

`nativeCallback<read_map_id>` 是注册函数指针，无隐藏 upvalue，也不修改正常返回值。C++ 意外异常经过此处时，实际函数中的资源已展开，再返回 `nil,{code="INTERNAL_ERROR",message=...}`；持续内存不足、无法构造错误结果时才进入 Lua 最终错误出口。领域错误继续由业务函数明确返回。

## 构建与 Sample

宿主必须先构建自己的 Skynet Lua，包含头文件和 `3rd/lua/liblua.a`。从 FlyWow 根目录执行：

```bash
bash scripts/build_flywow.sh /path/to/skynet lua_binding
bash lua-binding/sample/run_lua_binding_sample.sh /path/to/skynet
```

这两个命令在实际执行时都会使用指定 Skynet 自带 Lua ABI。构建入口先编译 `flywow_lua_binding` 并运行 `flywow_lua_binding_test`；Sample 脚本随后再编译、运行示例。Sample 成功标记为 `FLYWOW_LUA_BINDING_SAMPLE_OK`。文档中的标记是成功条件说明，不代表未执行命令时已经验证。

中间产物位于 `build/cmake/lua-binding/`，Sample 产物位于 `build/lua-binding-sample/`。宿主链接 `flywow_lua_binding`，不链接另一套系统 Lua。

## ABI 回归覆盖

真实 ABI 测试位于 `lua-binding/tests/lua_binding_test.cpp`，由 `bash scripts/build_flywow.sh /path/to/skynet lua_binding` 构建并经 CTest 执行。测试必须链接所传 Skynet v1.8.0 的 `3rd/lua/liblua.a`，不能以系统 Lua 替代。

测试使用独立 Lua State 检查：严格数值和字符串转换、失败时输出与栈恢复、table raw 读写和迭代、registry 引用释放、业务 upvalue 编号及大闭包、C++ 异常转换、Lua 分配失败时的 C++ 资源展开和 userdata 回收、动态 userdata 注册、静态 `require` 模块注册成功及 `__gc` 覆盖拒绝、析构幂等、State 隔离与关闭析构。测试覆盖的是 Binding 的 Lua ABI 和生命周期合同；它不代替 Gateway/Navigation 等各 Native 模块的宿主集成验证。

Sample 使用的是更小的真实调用示例；它会先触发上述 ABI 回归，再单独编译和运行示例程序。

## 三个类型与 ownership

| 类型 | 职责 | 生命周期 |
| --- | --- | --- |
| `LuaBinding` | 本次 Native 函数的参数、错误和结果；保活借用 userdata | 当前同步回调，不拥有 State |
| `LuaTable` | 用独立 registry 引用操作同一张表 | 早于所属 Binding 销毁，可移动、不可复制 |
| `LuaValue` | table 遍历中本轮 key/value 的只读视图 | 仅本次 visitor，有效期内不能复制或保存 |

父子 LuaTable 各持独立引用，可以独立销毁。将表写入别的表或返回给 Lua 后，句柄析构只释放自己的引用，不销毁 Lua 仍持有的表。句柄不能跨回调、跨 State 或 yield；同一 State 的不同 Binding 句柄也不能混用。

## 参数与字段

读取接口成功返回 true；类型、范围或已进入保护调用的 Lua 操作失败返回 false，记录 Binding 诊断。校验失败保持输出值不变。建立保护边界时的栈预留、C++ 字符串复制和诊断保存仍可能抛出 C++ 异常，统一由注册处的 nativeCallback 兜底；bool 不是“绝不抛异常”的承诺：

```cpp
binding.readValue(1, value);
binding.readOptionalValue(2, default_value);
binding.readTable(1, request);
request.readValue("map_id", map_id);
request.readTable("position", position);
request.writeValue("map_id", map_id);
request.writeValue(1, value);
request.writeValue("removed", nullptr);
```

`readOptionalValue` 只在参数省略或为 nil 时保留默认值。false、0、空字符串都是真实输入，按目标类型校验。严格 bool 读取仅接受 boolean；`readTruth` 显式采用 Lua 真值规则，只有 nil 和 false 为假。

整数转换检查目标 C++ 类型范围；整数接口不接受浮点 1.0 或数字字符串。浮点转换拒绝非有限值。`std::string` 保留内嵌零字节；C 字符串按首个零字节结束。

table 使用 raw 读写，不触发 `__index`、`__newindex`。普通表允许写入 `__gc` 字段。托管 userdata 元表的析构方法由类型注册入口设置；LuaTable 按实际元表与析构闭包身份拒绝后续删除或覆盖，换一个句柄也不会绕过保护。保护复用析构闭包的私有元数据，不增加注册表或句柄状态，也不改变业务方法的 upvalue 编号。直接使用原生 API 改写托管元表不在此保护合同内。

`isNil(key)` 对 nil 返回 true；非 nil 或无效句柄返回 false。使用者先检查 table 的创建/读取结果，不能用 isNil 代替句柄有效性检查。

## 创建和返回

```cpp
LuaTable output;
if (!binding.newTable(output))
{
    return binding.pushError();
}
if (!output.writeValue("accepted", false))
{
    return binding.pushError();
}
return binding.returnValues(output);
```

`newTable(output)` 创建成功才替换 output；不再返回对象并依赖外部入口结构报告分配失败。`returnValues` 支持零个或多个结果：

```cpp
return binding.returnValues();
return binding.returnValues(false);
return binding.returnValues(table, value);
return binding.pushError();
return binding.pushError("MY_ERROR", "operation failed");
```

结果按实参顺序交给 Lua。成功值允许 false 时，Lua 调用方使用 `result == nil` 判断失败。准备返回结果后立即 return，不另行弹栈。

## 注册方法与业务 upvalue

动态表注册采用编译期函数参数：

```cpp
if (!module.setFunction<read_map_id>("read_map_id"))
{
    return binding.pushError();
}
```

需要业务 upvalue 时，继续按顺序传入：

```cpp
module.setFunction<query>("query", registry_pointer);
```

回调通过 `readUpvalue(1, pointer)` 读取第一个真实业务 upvalue。注册入口不加入额外槽位。table 和托管 userdata 被闭包强引用；`void*` 仅借用外部对象，其 owner 必须覆盖闭包使用期。原始 Lua C API 注册也必须使用 `nativeCallback<实际函数>` 才具有相同的 C++ 异常合同。

模块初始化使用静态 `luaL_Reg` 表；不需要为注册模块创建 LuaTable 或 Binding 对象。初始化中若有 C++ 单例、容器等可能抛出的操作，应在局部 try/catch 中处理，并在资源与异常对象销毁后调用 Lua 错误出口。

## userdata

模块入口的静态注册接口：

```cpp
static const luaL_Reg methods[] =
{
    {"close", &LuaBinding::nativeCallback<close>},
    {nullptr, nullptr},
};
LuaBinding::registerUserdata<MyObject>(state, "example.MyObject", methods);
```

它安装受控的 `__gc`，并把 methods 表设置为 `__index`。类型名必须非空且在本 State 中唯一；methods 不能覆盖 `__gc`。失败沿 Lua 模块加载错误传播。

普通回调中创建和读取对象：

```cpp
MyObject *object = nullptr;
if (!binding.newUserdata("example.MyObject", object, constructor_argument))
{
    return binding.pushError();
}
return binding.returnValues(object);
```

`newUserdata` 先分配 Lua-owned 存储和禁用的 GC 标记，再在 C++ 作用域构造 T；构造成功才启用析构标记。T 必须 noexcept 析构并满足宿主 Lua 的对齐要求。参数错误、未注册类型、构造失败返回 false。已构造对象在后续失败时仍归 GC，析构时间可能晚于本函数返回。

`readUserdata` 验证精确元表与存活标记。T* 只在本 Binding 同步回调内借用，不得 delete、跨线程或长期保存。Binding 内部引用用于将指针还原为原 userdata 并防止借用期间被 GC。业务 close 释放内部资源；之后 GC 仍可安全调用析构。

动态注册场景仍可使用实例方法 `binding.registerUserdata<T>(name, meta)`。该接口返回 bool 和 metatable 句柄；模块入口优先使用静态注册。

## 遍历与数组

`forEach` 的 visitor 接收本轮 LuaValue key/value。读取不会转换原 key，嵌套 table 可变成独立 LuaTable 句柄。visitor 不得修改源表或 yield；false 表示失败，显式记录的新错误会保留，否则补 INTERNAL_ERROR。C++ 异常先恢复临时栈再交给注册入口。

`arrayLength` 返回 rawlen 边界，不保证无空洞；`denseArrayLength` 验证正整数 key 恰为 1..N，忽略其他 key，空表长度为 0。业务自己决定是否允许空数组。

## 内部维护入口

核心路径只有以下几种：

| 操作 | 内部执行 |
| --- | --- |
| 严格参数读取 | 原位检查类型与范围，不改变参数栈 |
| table 读写或函数注册 | 一个完整操作的一次 protectedCall，随后恢复临时栈 |
| C++ 业务处理 | 在普通函数作用域执行，由注册处兜底异常 |
| 模块加载 | 静态表直接注册，使用 Lua 加载错误合同 |

`protectedCall` 接收普通 Lua C 回调和明确的数据参数；内部回调只放 Lua C API，不创建需要析构的 C++ 局部资源。它返回成功标志，不再把 Lua 失败转换成内部异常再转回 Lua。已进入保护调用的 Lua 操作失败后，外层记录诊断并返回 false。建立保护边界时的栈预留、C++ 值复制和诊断保存可能抛异常；无法构造错误结果时也会展开到注册处。Native 注册入口负责在资源与异常对象析构后报告这些失败。

LuaTable 内部自动恢复临时栈；registry 引用保持对象身份。直接混用原生 Lua C API 时，调用者仍需处理自己的栈与 longjmp 边界。

## 迁移清单

| 旧写法 | 当前写法 |
| --- | --- |
| 入口 invoke 加 lambda | 直接函数体，注册 nativeCallback<函数> |
| 模块 invokeModule 加 lambda | 静态 luaL_Reg 直接注册 |
| `auto table = binding.newTable()` | `LuaTable table; binding.newTable(table)` 并检查 bool |
| `setFunction(name, callback, ...)` | `setFunction<callback>(name, ...)` |
