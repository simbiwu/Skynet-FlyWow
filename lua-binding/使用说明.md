# Lua Binding 使用说明

本模块把 Native Binding 中的 Lua 参数、table、返回值、闭包、metatable 和 userdata 操作集中到 C++ 封装。导航的真实接入见 `navigation/native/lua/src/lua_navigation.cpp`。

固定基线为 C++14、Skynet v1.8.0 自带修改版 Lua 5.4.7。实现只依赖 Lua 和 C++ 标准库，提供 PIC 静态 target `flywow_lua_binding`，由 Native 模块链接；测试另外使用宿主 `liblua.a` 和线程库。

## 三个类型

| 类型 | 用法与生命周期 |
| --- | --- |
| `LuaBinding` | 当前同步回调的参数、返回值、错误、upvalue、类型注册。由入口适配器创建 |
| `LuaTable` | 持有独立 registry 引用，可移动、不可复制。只在所属回调内使用 |
| `LuaValue` | `forEach` 本轮 key/value 的短期视图。不可复制、移动或保留 |

对象参数名使用 `lua_binding`；C++ 方法和函数使用 lowerCamelCase；Lua 可见的字段/方法使用 snake_case。

## 构建

从 FlyWow 根目录执行，Skynet 路径由调用者显式指定：

```bash
# 宿主 Skynet 已构建，包含它自己的 3rd/lua/liblua.a。
bash scripts/build_flywow.sh /path/to/skynet lua_binding

# 构建导航，同时运行封装与导航 CTest。
bash scripts/build_flywow.sh /path/to/skynet navigation
```

中间文件和独立测试位于 `build/cmake/lua-binding/`，导航最终产物仍为 `build/native/flywow_navigation_native.so`。没有独立的 Binding Lua 模块需要 require。

其它 Native 的 CMake 接入：

```cmake
# SKYNET_LUA_DIR 由宿主明确传入，指向它使用的固定 Lua 头文件。
if(NOT TARGET flywow_lua_binding)
    add_subdirectory("/path/to/skynet-flywow/lua-binding"
                     "${CMAKE_BINARY_DIR}/lua-binding" EXCLUDE_FROM_ALL)
endif()
target_link_libraries(your_native PRIVATE flywow_lua_binding)
```

路径是开发者在构建阶段提供的路径，不进入 Runtime 配置。不要链接系统 Lua。

## 最小 Binding

```cpp
#include "lua_binding.h"
#include "lua_table.h"

using flywow_lua_binding::LuaBinding;
using flywow_lua_binding::LuaTable;

/// 读取 request.map_id；失败返回 nil,{code,message}，0 是合法的 uint32。
int readMapId(LuaBinding &lua_binding)
{
    LuaTable request;
    std::uint32_t map_id = 0; // 从请求读取，不用数值 0 判断读取是否成功。
    if (!lua_binding.readTable(1, &request) ||
        !request.readValue("map_id", &map_id))
    {
        return lua_binding.pushError();
    }

    auto result = lua_binding.newTable();
    if (!result.writeValue("map_id", map_id))
    {
        return lua_binding.pushError();
    }
    return lua_binding.returnValues(result);
}

int initializeModule(LuaBinding &lua_binding)
{
    auto module = lua_binding.newTable();
    if (!module.setFunction("read_map_id", &readMapId))
    {
        return lua_binding.pushError();
    }
    return lua_binding.returnValues(module);
}

extern "C" int luaopen_your_native(lua_State *state)
{
    return LuaBinding::initialize(state, &initializeModule);
}
```

Lua 调用方检查首个结果：

```lua
local result, err = native.read_map_id({ map_id = 0 })
if not result then
    return nil, err
end
```

普通回调不使用 Lua C API，也不维护压栈、弹栈或返回数量。C ABI 导出入口只转交初始化适配器。

上例成功返回 Table，可以用 if not result 判断。如果某个 API 的成功值允许为 false，应使用 result == nil 判断失败，避免把合法的 false 当成错误。

## 读取和写入

```cpp
lua_binding.readValue(1, &value);   // 位置参数，类型通常由输出指针推导。
lua_binding.readTable(1, &table);
lua_binding.readTable(&table);     // 调用瞬间真实栈顶，仍检查它确实是 table。
table.readValue("name", &value);   // 字符串 key。
table.readValue(0, &value);        // 真实整数 key，0/负数也合法。
table.readTable("child", &child);
table.readTable(1, &child);
table.writeValue("name", value);
table.writeValue(0, value);
table.writeValue("obsolete", nullptr); // 删除字段。
```

读取返回 bool，输出指针非空，失败不改变原值或原 Table 句柄。数值 0、bool false、空字符串都可正常读取。支持标准整数、float/double、bool、std::string；不支持的 T 在编译期报错。

整数必须为 Lua integer，写入 uint64 不能超过 Lua 有符号整数范围。bool 严格要求 boolean。float/double 接受真正的 Lua number/integer、拒绝非有限值与越界，允许正常精度舍入。std::string 和字段 key 保留内嵌零字节。

Table 读写使用 raw 访问，不触发 `__index`/`__newindex`；`isNil(key)` 用于判断缺省字段；`readTruth(key,&value)` 明确使用 Lua 真值规则，数字 0 和空串为真。

同一逻辑组的变量声明、赋值符和行尾注释按列对齐；变量注释解释来源、单位、默认值和生命周期等非显然语义。

## 返回和错误

```cpp
return lua_binding.returnValues();             // 无返回值。
return lua_binding.returnValues(value);
return lua_binding.returnValues(table, value); // 按顺序返回多个值。
return lua_binding.pushError();                // 最近一次记录的错误。
return lua_binding.pushError("MY_ERROR", "诊断说明");
```

准备结果后立即 return。Table 从 registry 另压一份引用；局部句柄析构只 unref，Lua 仍会收到结果。无需 close、pop 或 std::move 返回 Table。

读取/写入失败记录错误，不暗中压入错误结果；调用方检查 bool。业务解析器用 `setError(code,message)` 记录失败。成功操作不自动抹掉已处理的旧错误。可以用 `errorCode()/errorMessage()` 读取最近错误。

外部失败统一为 `nil,{code,message}`：类型/参数/范围错误为 INVALID_ARGUMENT；业务可提供自己的稳定 code；未处理 C++ exception 或没有准备返回值为 INTERNAL_ERROR。普通错误正常返回，入口捕获 C++ exception，局部 RAII 对象正常析构。初始化 ABI 检查在业务对象创建前执行。

## 遍历和数组

```cpp
bool success = table.forEach(
    [&](const flywow_lua_binding::LuaValue &key,
        const flywow_lua_binding::LuaValue &value)
    {
        // 根据 key.type()/value.type() 读取；每个 readValue/readTable 的 bool 都应检查。
        // 例如业务要求所有 value 都是整数：
        int number = 0;
        return value.readValue(&number);
    });
if (!success)
{
    return lua_binding.pushError();
}
```

visitor 返回 true 继续，false 表示处理失败并停止；需要业务错误时先 setError。未记录新错误就返回 false，封装补 INTERNAL_ERROR；不会误用之前已处理的错误。回调内用 bool 返回，不在 visitor 中准备 Native 的最终返回值。

顺序未定义；可以嵌套读取/遍历其它表。遍历期间不要修改源表或 yield；LuaValue 只在本轮有效。需要后续使用子表时，显式 readTable 成独立 LuaTable。

`arrayLength(&length)` 给出 rawlen 边界。`denseArrayLength(&length)` 用 O(字段数) 时间、O(1) 额外空间检查正整数 key 是否构成 1..N，忽略命名字段、0、负数及非整数 key；空数组成功返回 0。是否允许空由业务决定，普通 Table 读写不自动执行稠密检查。

## 闭包、metatable 和 userdata

`table.setFunction(name,callback,upvalues...)` 同时用于普通函数、闭包和元方法；callback 为 `int(LuaBinding&)` 函数指针或无捕获函数。业务 upvalue 从 1 编号，最多 254 个；封装的 callback 描述占据内部第一槽。

读取和更新用 `readUpvalue(index,&value)`、`readUpvalueTable(index,&table)`、`writeUpvalue(index,value)`。Table/userdata 由闭包强引用；显式 void* 为借用 lightuserdata，其 owner 必须比闭包活得久。函数指针不转成 void*。

metatable 仍使用 LuaTable：`registerMetatable(name,&meta,&created)` 首次返回 created=true，重复注册取得已有表，不自动覆盖；`table.setMetatable(meta)`/`readMetatable(&meta)` 设置或取得表；`meta.writeValue("__index",methods)` 指向方法表。

userdata 只有注册、创建、读取三组操作：

```cpp
LuaTable meta;
bool created = false;
if (!lua_binding.registerUserdata<MyType>("module.MyType", &meta, &created))
{
    return lua_binding.pushError();
}

MyType *object = nullptr; // GC 管理对象，本回调借用，不能手动 delete。
if (!lua_binding.newUserdata("module.MyType", &object, constructor_args))
{
    return lua_binding.pushError();
}
return lua_binding.returnValues(object);
```

`readUserdata(index,name,&object)`、`table.readUserdata(key,name,&object)` 和 `readUpvalueUserdata(index,name,&object)` 验证精确 T、大小、metatable、存活状态。读取/创建时封装持有本回调的短期引用，使原 userdata 可以写表、返回或进入闭包。任意 T* 不会被自动包装成 full userdata。

T 必须 noexcept 析构，对齐不超过宿主 Lua userdata 的保证。同名不同 T 拒绝注册。先挂统一 GC，再构造 T；构造失败不会调用未构造对象的析构。GC 先标记已析构再执行 ~T，重复 GC 不重复析构。普通字段写入或方法注册不能覆盖封装的 GC 和类型标记。

导航 `context:close()` 幂等释放大块 Context 内存，关闭后业务访问返回 CONTEXT_CLOSED；userdata 外壳及 profiles/vector 最后由统一 GC 析构。

## 生命周期与兼容

所有句柄和借用指针限所属 Lua State 的当前同步回调；不保存到全局、跨回调、跨线程或跨 yield。每个 State 由自己的 owner 顺序使用；不同 State 可以在不同 OS Thread 并发使用封装。实现无可变进程级 scratch，也不拥有 VM 或 Skynet Service。

Navigation 的 Lua 名称、方法、参数、毫米坐标和领域错误码保持原合同。此轮仅迁移 Navigation，其它 Native 可以按后续任务链接同一静态 target；业务层不必调整 Lua 调用方式。

## 验证入口

统一构建脚本会执行真实宿主 Lua ABI 测试，覆盖范围见 `tests/lua_binding_test.cpp`：

- 标准值、0/false/空串、整数边界、非有限浮点、失败不改输出。
- raw 表访问、真实整数 key、嵌套/移动/引用释放、返回 Table 与栈平衡。
- 稀疏/空数组、混合 key、嵌套遍历、失败/异常和数值 key 不变形。
- upvalue 映射和最大数量、metatable 身份、类型冲突、构造失败及重复 GC。
- 多 State 隔离、多 OS Thread 的独立 State、C++ exception 不越过 ABI。

测试输出 READ_TABLE_100000，比较同进程中重复 100000 次的固定 raw 参数读取与封装 table/字段读取。它只衡量该调用形态的 registry 引用等成本，不能代表导航算法或服务器容量。

真实导航集成测试从 FlyWow 根目录运行：

```bash
SKYNET_LUA=/path/to/skynet/3rd/lua/lua \
NAVIGATION_NATIVE_DIR=build/native \
python3 -m unittest discover -s navigation/tests -p test_navigation_binding.py
```

封装的 Lua C API 注释集中在 lua_binding.cpp、lua_table.cpp 和模板内部，讲清栈变化、索引、raw 行为及资源生命周期。公开头文件使用 Doxygen 兼容注释供 IDE 阅读。
