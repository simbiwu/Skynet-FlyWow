# Lua Binding 使用说明

本模块把 Native Binding 中的 Lua 参数、table、返回值、闭包、metatable 和 userdata 操作集中到 C++ 封装。导航的真实接入见 `navigation/native/navigation_binding.cpp`。

固定基线为 C++17、Skynet v1.8.0 自带修改版 Lua 5.4.7。实现只依赖 Lua 和 C++ 标准库，提供 PIC 静态 target `flywow_lua_binding`，由 Native 模块链接；测试另外使用宿主 `liblua.a` 和线程库。

## 三个类型

| 类型 | 用法与生命周期 |
| --- | --- |
| `LuaBinding` | 当前 Lua C 回调的参数、返回值、错误、upvalue、类型注册；回调内按需直接构造 |
| `LuaTable` | 持有独立 registry 引用，可移动、不可复制。只在所属回调内使用 |
| `LuaValue` | `forEach` 本轮 key/value 的短期视图。不可复制、移动或保留 |

对象参数名使用 `lua_binding`；C++ helper 使用 lowerCamelCase；直接注册的回调与 Lua snake_case 名称一致。Lua 名称是 C++ 关键字或保留标识符时，使用合法且明确的回调名，并在注册处说明例外。

## 构建

从 FlyWow 根目录执行，Skynet 路径由调用者显式指定：

```bash
# 宿主 Skynet 已构建，包含它自己的 3rd/lua/liblua.a。
bash scripts/build_flywow.sh /path/to/skynet lua_binding

# 构建导航，同时运行封装与导航 CTest。
bash scripts/build_flywow.sh /path/to/skynet navigation
```

中间文件和独立测试位于 `build/cmake/lua-binding/`，导航最终产物仍为 `build/native/flywow_navigation_native.so`。没有独立的 Binding Lua 模块需要 require。

其它 Native 的 CMake 接入：

```cmake
# SKYNET_LUA_DIR 由宿主明确传入，指向它使用的固定 Lua 头文件。
if(NOT TARGET flywow_lua_binding)
    add_subdirectory("/path/to/skynet-flywow/lua-binding"
                     "${CMAKE_BINARY_DIR}/lua-binding" EXCLUDE_FROM_ALL)
endif()
target_link_libraries(your_native PRIVATE flywow_lua_binding)
```

路径是开发者在构建阶段提供的路径，不进入 Runtime 配置。不要链接系统 Lua。

## 最小 Binding

```cpp
#include "lua_binding.h"
#include "lua_table.h"

using flywow_lua_binding::LuaBinding;
using flywow_lua_binding::LuaTable;

/// Lua 调用 read_map_id，读取 request.map_id 后返回同值结果表。
/// @param state 参数 1 为请求表，map_id 必须是 uint32，0 合法。
/// @return 成功返回结果表；失败返回 nil,{code,message}。
int read_map_id(lua_State *state)
{
    return LuaBinding::invoke(state, [state]() -> int
    {
        LuaBinding lua_binding(state);
        LuaTable request;          // 借用输入表，引用只在本次 Binding 中持有。
        std::uint32_t map_id = 0;   // 请求地图编号，读取成功由 bool 判断。
        if (!lua_binding.readTable(1, request) || !request.readValue("map_id", map_id))
        {
            return lua_binding.pushError();
        }

        auto result = lua_binding.newTable(); // 返回表在压入 Lua 结果后继续存活。
        if (!result.writeValue("map_id", map_id))
        {
            return lua_binding.pushError();
        }
        return lua_binding.returnValues(result);
    });
}

/// require 通过此入口加载模块；成功给出模块表，初始化失败报告加载错误。
/// @param state Lua 加载器提供的当前栈。
/// @return 成功返回一个模块表；失败不正常返回。
extern "C" int luaopen_your_native(lua_State *state)
{
    return LuaBinding::invokeModule(state, [state]() -> int
    {
        LuaBinding lua_binding(state);
        auto module = lua_binding.newTable(); // 仅在注册全部完成后交给 require。
        if (!module.setFunction("read_map_id", &read_map_id))
        {
            return lua_binding.pushError();
        }
        return lua_binding.returnValues(module);
    });
}
```

回调使用 Lua C API 的标准签名 `int(lua_State *)`，再按需构造 `LuaBinding` 使用值操作封装。模块入口在 `invokeModule` 内直接建表并注册；普通回调在 `invoke` 内执行完整业务流程。函数注册直接建立 Lua C 闭包；返回值数量由回调的 `returnValues` 或 `pushError` 返回，不另做栈高度核验。

Lua 调用方检查首个结果：

```lua
local result, err = native.read_map_id({ map_id = 0 })
if not result then
    return nil, err
end
```

回调可使用 Lua C API，也可用 LuaBinding/LuaTable 处理常见值操作；Lua C API 需要的栈行为由回调按 Lua 规则负责。

上例成功返回 Table，可以用 if not result 判断。如果某个 API 的成功值允许为 false，应使用 result == nil 判断失败，避免把合法的 false 当成错误。

## 读取和写入

```cpp
lua_binding.readValue(1, value);   // 位置参数，类型由输出对象推导。
lua_binding.readTable(1, table);
lua_binding.readTable(table);     // 调用瞬间真实栈顶，仍检查它确实是 table。
table.readValue("name", value);   // 字符串 key。
table.readValue(0, value);        // 真实整数 key，0/负数也合法。
table.readTable("child", child);
table.readTable(1, child);
table.writeValue("name", value);
table.writeValue(0, value);
table.writeValue("obsolete", nullptr); // 删除字段。
```

读取返回 bool，输出参数使用引用；userdata 的输出是指针引用，失败保留调用者原值。数值 0、bool false、空字符串都可正常读取。支持标准整数、float/double、bool、std::string；不支持的 T 在编译期报错。

整数必须为 Lua integer，写入 uint64 不能超过 Lua 有符号整数范围。bool 严格要求 boolean。float/double 接受真正的 Lua number/integer、拒绝非有限值与越界，允许正常精度舍入。std::string 和字段 key 保留内嵌零字节。

Table 读写使用 raw 访问，不触发 `__index`/`__newindex`；`isNil(key)` 用于判断缺省字段；`readTruth(key, value)` 明确使用 Lua 真值规则，数字 0 和空串为真。

同一逻辑组的变量声明、赋值符和行尾注释按列对齐；变量注释解释来源、单位、默认值和生命周期等非显然语义。

## Lua 栈与 C API 注释

业务 Binding 通过 LuaBinding/LuaTable 读取参数时，read 接口不改变回调入口栈；LuaTable 以 registry 引用短暂保活 table，不要求调用方保留栈槽。写表、读字段和遍历产生的临时栈值由方法内的 StackRestore 恢复。读取一律使用 raw API，不触发元方法。

返回时，returnValues 只把声明的结果压到栈顶并立即返回其数量；pushError 压入 nil 和错误 table，也应立即返回。Lua 在回调返回时取栈顶 N 项作为结果，并清理其下的临时项。不要在业务回调重复弹栈或自行校正高度。

Lua C API 的实现注释放在 lua_binding.cpp、lua_table.cpp 和模板内部：关键组说明入口/出口栈、正负索引、raw 访问、lua_next 保留 key 的规则，以及 registry 引用、userdata 析构和 longjmp 边界。调用点只补该业务记录的输入含义与 owner，不重复讲解相同的栈机制。

## 返回和错误

```cpp
return lua_binding.returnValues();             // 无返回值。
return lua_binding.returnValues(value);
return lua_binding.returnValues(table, value); // 按顺序返回多个值。
return lua_binding.pushError();                // 最近一次记录的错误。
return lua_binding.pushError("MY_ERROR", "诊断说明");
```

准备结果后立即 return。Table 从 registry 另压一份引用；局部句柄析构只 unref，Lua 仍会收到结果。无需 close、pop 或 std::move 返回 Table。

有 owner 的读取/写入失败记录错误，不暗中压入错误结果；调用方检查 bool。默认或移动后的失效 LuaTable 没有 owner，只能返回 false，不能向任意 Binding 写入错误。业务解析器用 `setError(code,message)` 记录失败。成功操作不自动抹掉已处理的旧错误。可以用 `errorCode()/errorMessage()` 读取最近错误。

可报告的 API 失败统一为 `nil,{code,message}`：类型/参数/范围错误为 INVALID_ARGUMENT；业务可提供自己的稳定 code。回调按 Lua C API 约定直接返回结果数量；不会再检查回调声明数量与栈高度是否一致。

## 遍历和数组

```cpp
bool success = table.forEach(
    [&](const flywow_lua_binding::LuaValue &key,
        const flywow_lua_binding::LuaValue &value)
    {
        // 根据 key.type()/value.type() 读取；每个 readValue/readTable 的 bool 都应检查。
        // 例如业务要求所有 value 都是整数：
        int number = 0;
        return value.readValue(number);
    });
if (!success)
{
    return lua_binding.pushError();
}
```

visitor 返回 true 继续，false 表示处理失败并停止；C++ 异常恢复遍历栈后继续传播到外层 invoke，不转换成 false；需要业务错误时先 setError。未记录新错误就返回 false，封装补 INTERNAL_ERROR；不会误用之前已处理的错误。回调内用 bool 返回，不在 visitor 中准备 Native 的最终返回值。

顺序未定义；可以嵌套读取/遍历其它表。遍历期间不要修改源表或 yield；LuaValue 只在本轮有效。需要后续使用子表时，显式 readTable 成独立 LuaTable。

`arrayLength(length)` 给出 rawlen 边界。`denseArrayLength(length)` 用 O(字段数) 时间、O(1) 额外空间检查正整数 key 是否构成 1..N，忽略命名字段、0、负数及非整数 key；空数组成功返回 0。是否允许空由业务决定，普通 Table 读写不自动执行稠密检查。

## 闭包、metatable 和 userdata

`table.setFunction(name,callback,upvalues...)` 注册 `int(lua_State *)` 回调，并直接用传入值创建 Lua 闭包。业务从 `readUpvalue(1,...)` 开始读取 Lua 的第一个真实 upvalue；没有内部描述槽或编号偏移。upvalue 数量保持为回调实际需要的状态。注册按固定 Lua 5.4 的 255 项上限在编译期检查，临时压栈与多返回值均显式保证容量。非法 upvalue 编号返回 INVALID_ARGUMENT，0 不会映射成 registry。

读取和更新用 `readUpvalue(index, value)`、`readUpvalueTable(index, table)`、`writeUpvalue(index,value)`。Table/userdata 由闭包强引用；显式 void* 为借用 lightuserdata，其 owner 必须比闭包活得久。函数指针不转成 void*。

metatable 仍可作为普通 `LuaTable` 操作；userdata 的 `registerUserdata<T>(name, meta)` 一次完成具名 metatable 注册和 GC 设置。方法表通过 `meta.writeValue("__index", methods)` 关联；普通 table 仍可用 `setMetatable`/`readMetatable`.

userdata 只有注册、创建、读取三组操作：

```cpp
LuaTable meta;
if (!lua_binding.registerUserdata<MyType>("module.MyType", meta))
{
    return lua_binding.pushError();
}

MyType *object = nullptr; // GC 管理对象，本回调借用，不能手动 delete。
if (!lua_binding.newUserdata("module.MyType", object, constructor_args))
{
    return lua_binding.pushError();
}
return lua_binding.returnValues(object);
```

`readUserdata(index,name,object)`、`table.readUserdata(key,name,object)` 和 `readUpvalueUserdata(index,name,object)` 按具名 metatable 读取 userdata。读取/创建时封装持有本回调的短期引用，使原 userdata 可以写表、返回或进入闭包。任意 T* 不会被自动包装成 full userdata。

T 必须 noexcept 析构并满足宿主 Lua 的 userdata 对齐保证，编译期拒绝 over-aligned 类型。同一 metatable 名称只用于一种 T，由模块注册代码保持一致。userdata 内存直接存放 T；先以未构造标记安装对应 GC，构造成功后才标记存活，Lua 回收时只析构活对象。Binding 记录析构状态，防止重复 finalize 导致二次析构；析构后的 userdata 读取会返回 INVALID_ARGUMENT。调用方仍不应手动调用 __gc。构造失败时 GC 保持未激活，不析构未构造对象；构造成功后再失败时，由已安装的 GC 稍后析构。普通字段写入或方法注册不能覆盖注册操作设置的 __gc。

导航 `context:close()` 幂等释放大块 Context 内存，关闭后业务访问返回 CONTEXT_CLOSED；userdata 中的 Context 及其 profiles/vector 最后由 Lua 自动 GC 析构。

## Lua 分配与 C++ 异常

`invoke`/`invokeModule` 的 lambda 只捕获借用参数，所有需要析构的 C++ 资源在 lambda 内声明。普通 API 的成功返回和参数失败不变；意外 C++ 异常转换为 `nil,{code="INTERNAL_ERROR",message=...}`。已有领域入口可以在 lambda 内先处理自己的稳定错误码，例如 Navigation 的容量错误。

封装内可能分配的字符串、table、closure、registry 引用、userdata 和字段写入在 Lua 的 `pcall` 内执行。内部操作只用不持有 C++ 资源的 C API 代码；失败先返回外层，再用不分配内存的 C++ 标记展开 RAII。保护调用的内部参数不进入业务闭包，upvalue 仍从 1 开始。恢复入口栈只清理临时槽，不撤销已经完成的表字段或业务状态变化。

若 Lua 持续 OOM，连错误 record 也无法分配，`invoke` 在业务资源和异常对象清理后按 Lua 原生错误传播，调用方可用 `pcall` 处理；不能承诺内存耗尽时仍能返回新建错误表。模块初始化失败始终按加载错误传播，避免 `require` 将 nil 模块结果记为 true。

`newTable()` 成功返回有效句柄；分配失败走上述异常边界，不存在普通的“返回失效句柄”分支。直接混用原生 Lua C API 时，分配、longjmp 与业务资源边界仍由调用方负责；不要让原生抛错越过活的 C++ 资源。

## 生命周期与兼容

所有句柄和借用指针限所属 Lua State 的当前同步回调；不保存到全局、跨回调、跨线程或跨 yield。每个 State 由自己的 owner 顺序使用；不同 State 可以在不同 OS Thread 并发使用封装。实现无可变进程级 scratch，也不拥有 VM 或 Skynet Service。

Navigation 的 Lua 名称、方法、参数、毫米坐标和领域错误码保持原合同。本次同时迁移 Gateway、Navigation、Word Filter 和 HotUpgrade 的 Native 回调；Lua 可见的业务函数合同保持不变。

## 验证入口

统一构建脚本会执行真实宿主 Lua ABI 测试，覆盖范围见 `tests/lua_binding_test.cpp`：

- 标准值、0/false/空串、整数边界、非有限浮点、失败不改输出。
- raw 表访问、真实整数 key、嵌套/移动/引用释放、返回 Table 与栈平衡。
- 稀疏/空数组、混合 key、嵌套遍历、失败路径和数值 key 不变形。
- 原生 upvalue 读取/更新、metatable 身份、构造成功/失败及自动 GC 析构。
- 多 State 隔离、多 OS Thread 的独立 State。
- 64 个返回值、64 个业务 upvalue、非法读写编号和输出保留。
- 普通 table 自动 GC、错误 userdata/非 userdata 调用 collector 的类型边界。
- 32 个真实 Lua 分配故障点：持续拒绝增长分配，恢复 allocator 后核对 C++ 资源与 userdata 析构。
- C++ bad_alloc/意外异常转换，以及 require 初始化失败不缓存 true。

测试输出 READ_TABLE_100000，比较同进程中重复 100000 次的固定 raw 参数读取与封装 table/字段读取。它只衡量该调用形态的 registry 引用等成本，不能代表导航算法或服务器容量。

真实导航集成测试从 FlyWow 根目录运行。Native 依赖宿主导出的 je_malloc/je_free；独立 Lua 必须在启动时显式加载同版本 Skynet jemalloc，共享库文件须已经存在。Skynet 进程自身不需要此测试用环境变量，见 [Native 内存合同](../docs/native-memory.md)：

```bash
LD_PRELOAD=/path/to/skynet/3rd/jemalloc/lib/libjemalloc.so.2 \
SKYNET_LUA=/path/to/skynet/3rd/lua/lua \
NAVIGATION_NATIVE_DIR=build/native \
python3 -m unittest discover -s navigation/tests -p test_navigation_binding.py
```
